# Навигация в браузере

Разделы кабинетов и формы входа имеют собственные адреса. «Назад» и «Вперёд» возвращают к экрану; обновление страницы и открытие ссылки в новой вкладке сохраняют выбранный раздел. При необходимости сначала показывается вход.

В историю также входят:

- открытая попытка теста и её результат;
- банк кандидатов с применёнными фильтрами;
- режим подбора и конкретная сохранённая подборка;
- окно приглашения кандидату;
- открытый диалог по приглашению.

Сервер остаётся источником данных и прав доступа. Он не отправляет заново сообщения, приглашения или ответы и не отменяет выполненные действия. После выхода из аккаунта история не открывает кабинет без нового входа. Несуществующий или чужой раздел заменяется обзором; недоступные результаты и диалоги не раскрываются.

При уходе из открытого теста с несохранёнными ответами появляется подтверждение. При отмене адрес и экран остаются прежними; при согласии черновик остаётся в браузере. Аналогично защищено редактируемое окно приглашения. Срок теста продолжает идти независимо от навигации. Введённые значения полей и каждое нажатие кнопки не являются отдельными шагами истории.

На длинных страницах восстанавливается позиция прокрутки. Кнопка «Вперёд» доступна, только когда в браузере есть последующая запись истории. Новый переход после «Назад» заменяет последующую ветку истории, как на обычных сайтах.

## Реализация

`apps/web/src/navigation.ts` использует History API без дополнительных зависимостей. В состоянии истории хранятся номер записи и прокрутка; пароли, токены и ответы туда не записываются. Токены почтовых ссылок удаляются из адреса после обработки. Для прямых адресов nginx отдаёт `index.html`, сохраняя отдельное проксирование `/api/`.

## Проверка

Из корня проекта с установленными зависимостями и Chromium:

```bash
npm run build --prefix apps/web
python3 scripts/run_local.py .venv/bin/python tests/browser_navigation.py
FSP_AUTH_EVIDENCE=audit/current/navigation-auth python3 scripts/run_local.py .venv/bin/python scripts/check_auth_browser.py
```

Первый сценарий создаёт временную PostgreSQL-базу `fsp_navigation_*`, поднимает API и собранный frontend на `127.0.0.1:18084`, проверяет оба кабинета и мобильный размер экрана, затем удаляет свою временную базу. Нужны права создания тестовых баз. Рабочие аккаунты не изменяются, внешние письма не отправляются. Результат записывается в `audit/current/navigation/result.json`.

Второй сценарий отдельно проверяет регистрацию, подтверждение почты, восстановление пароля и ошибки SMTP, используя собственную базу и имитацию почтового сервера. Это автоматические проверки Chromium, включая мобильный размер окна, а не новый ручной проход на реальном телефоне.

Результат 21 октября 2026: сборка прошла, 10 групп проверок навигации и 8 проверок регистрации/почты прошли без ошибок JavaScript. [Отчёт](delivery/evidence/navigation_2026-10-21.json).

После обновления web-контейнера переходы, прямые ссылки, обновление страницы и выход дополнительно проверены на публичном HTTPS-сайте в обоих демо-кабинетах.
