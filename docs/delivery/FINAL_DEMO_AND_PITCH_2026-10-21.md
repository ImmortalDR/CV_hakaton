# Демонстрация и ответы перед финалом

Продолжительность финального выступления нужно подтвердить у организаторов. Ниже репетиционный маршрут; он не объявляется регламентом. Проверку человеком 25–40 минут провести отдельно до выступления.

## Маршрут без ожидания ограничений

1. Готовый кандидат: показать категорию, подтверждения навыков и отсутствие обязательного ФСП. Для демонстрации начала теста открыть отдельного fresh_python; показать восемь заданий, сохранение черновика и отмену завершения с пропусками. Не решать весь тест на сцене.
2. Работодатель: задать потребность, показать категорию, общий балл и конкретный непроверенный навык. Объяснить: частичный результат допустим, пробел не скрыт; порядок внутри категории по баллу.
3. Приглашение: компания, реальные границы зарплаты и предложение видны до отправки. Кандидат принимает, контакты открываются этой компании; другой работодатель остаётся без контактов.
4. Диалог и регулярное задание: показать ответ/оценку работодателя и дату следующей выдачи. Оценка работодателя не изменяет автоматический грейд. Пауза/возобновление не создаёт ранний дубль.
5. Отозвать публикацию: профиль/контакты/PDF/диалог закрываются, включая старую подборку. Повторная публикация не возвращает старое согласие.

Для живого показа подготовить отдельные браузерные профили. Не использовать одинаковый аккаунт для черновика, пропусков и независимой SQL-проверки после исчерпания попытки. На случай сети использовать честно подписанные скриншоты актуального прогона, не изображать видео как живую работу.

## Короткие ответы на трудные вопросы

- **Как строится грейд?** По серверной версионной рубрике: восемь задач, минимум шесть верных и три из четырёх по основному навыку. Провал не понижает уже подтверждённый уровень. Это текущая ограниченная проверка, не сертификат рыночного Senior.
- **Почему эти веса?** Действующая политика — общий тест и доказательства навыков с ограниченным бонусом ФСП. Старый контрольный набор не доказал рост P@5. Новый challenge показывает спорные перестановки, но независимую полезность для бизнеса ещё должен проверить пилот.
- **Модель обучена на всех реальных данных?** Нельзя так говорить о текущем ранжировании: это прозрачная формула с серверными доказательствами. Данные откликов не являются разметкой профессионального навыка. Исследовательские модели и продукционный подбор нужно объяснять отдельно.
- **Можно помочь себе LLM?** Да, запретить внешнюю помощь этими числовыми заданиями нельзя. Уникальные параметры и серверный эталон не доказывают самостоятельность. Следующий проверяемый шаг — практическая задача и пилот, а не обещание «античит решён».
- **Что даёт ФСП?** Ограниченный бонус внутри категории; не повышение грейда. Сейчас источник демонстрационный, официальный API не получен.
- **Что проверили реально?** 116 backend-тестов, 22 группы живого браузерного сценария, реальное письмо и вход, нагрузка и перезапуск. Числа проверки тестового банка — вычисления/симуляции, не люди.
- **Что нашли после проверки?** Ошибки интерфейса, N+1 и конкурентный сбой PDF; исправили и сохранили отрицательные и положительные протоколы. Не обещаем промышленную нагрузку по короткому прогону.
- **Где актуальный код?** Пока локально и на стенде; push пользователь отложил. Перед фактической сдачей обязательно опубликовать и проверить ссылки. Не говорить, что последняя версия уже на GitHub.
