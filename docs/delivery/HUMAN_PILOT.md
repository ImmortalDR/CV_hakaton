# Реальный пилот и ревью методик

Подготовлены 12 форм: A/B для каждой из шести категорий, по восемь вопросов.
Локальный комплект: `/root/hakaton/audit/human-pilot-v2/`.
Он содержит forms.json без ответов, отдельный answer-key.json с правами 0600,
пустые participants.csv/responses.csv, таблицу экспертного ревью 24 семейств
и манифест SHA-256. Ответы и персональные данные не публикуются автоматически.

## Перед сбором данных

1. Тимофей/профильные проверяющие читают задания и решения; в expert-review.csv
   фиксируют правильность, неоднозначность, соответствие заявленному уровню,
   свой код и конкретное замечание. Пустые клетки не означают одобрение.
2. До прохождения теста заполняют независимое ожидание по участнику:
   participant_id (псевдоним), специализация, выбранный уровень,
   independent_expected_pass=true/false и источник label_source.
   Если оснований нет, оба поля оставляют пустыми; согласие с эталоном не считается.
   Нельзя брать метку из оцениваемого теста или автоматически из резюме.
3. Фиксируют критерии и не меняют их по финальным результатам. Если правила
   изменены после пилота, для итоговой проверки нужна новая отдельная выборка.
4. Один участник проходит A и B в своей категории без подсказок/эталонов.
   Порядок чередуют A→B/B→A, записывают интервал и условия отдельно. До второго
   прохождения не показывают разбор первого. Не использовать демосайт для слепой
   пары: он раскрывает ответы сразу после сдачи. Использовать формы вне сайта.

Число участников выбирается под доступные ресурсы и точность оценки. Один
человек или одна группа не дают оснований заявлять валидность на рынке.
Способ набора, опыт, независимый источник оценки и отклонения протокола
описываются в отчёте без раскрытия лишних персональных данных.

## Ввод и расчёт

В responses.csv одна строка на каждый ответ: participant_id, form_id,
question_id, answer. Неразрешённый вопрос отмечается явной пустой строкой ответа;
неполные попытки скрипт отклоняет. Дубликаты, неверные категории, посторонние
вопросы и изменения замороженных форм/ключей также отклоняются.

```bash
PYTHONPATH=apps/api:. .venv/bin/python -m evaluation.pilot prepare --root audit/new-pilot
PYTHONPATH=apps/api:. .venv/bin/python -m evaluation.pilot evaluate --root audit/new-pilot
```

prepare разрешён только для пустого каталога. evaluate сохраняет results.json
локально. Считает согласие с независимыми метками, матрицу ошибок, совпадение
A/B по участникам и разность долей правильных ответов между независимо
заданными положительной/отрицательной группами по семействам. Нет второй группы
или пары — показатель null, а не фиктивные 100%. Единица повторного наблюдения —
человек; вопросы и все пары нельзя выдавать за независимых испытуемых.

На пустых шаблонах результат **not_run, 0 участников, 0 попыток**. Автоматические
тесты инструмента используют явно искусственные строки и не включаются в пилот.
Сервисная БД и подтверждённые пользовательские грейды этим инструментом не меняются.

## Что проверить в датасете подбора

Существующие метки являются программными контрольными сценариями. Реалистичность
должна проверяться отдельно: сочетания навыков, заявленного опыта и специализации;
полнота/противоречия; отсутствие истории ФСП; допустимость полного/частичного
соответствия; отсутствие совпадений; достаточно ли сведений для отказа или нужен
unknown. Не повышать ожидаемый грейд на основании текстового резюме.

При обсуждении спорных пар сохранять ID, старую метку, независимое обоснование
и источник. Исходную опубликованную разметку 1.0.0 не менять задним числом ради
метрик; исправления выпускаются отдельной версией. Пока человеческих заключений
нет, старый test остаётся регрессионным набором, а не слепым внешним экзаменом.
