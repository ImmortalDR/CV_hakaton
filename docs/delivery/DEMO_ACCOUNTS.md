# Общие демонстрационные аккаунты

Кнопки «Я кандидат» и «Я работодатель» открывают два постоянных аккаунта. Они общие для всех посетителей. Для одновременной проверки ролей используйте обычное окно и инкогнито либо разные браузеры.

После часа без действий в обоих аккаунтах они автоматически возвращаются к исходному примеру. Проверка планировщиком выполняется раз в минуту. Вход после истечения часа также запускает восстановление. Пока кто-либо пользуется любым из этих аккаунтов, общий таймер продлевается. Клики, ввод, прокрутка и возвращение в видимое окно считаются активностью; фоновый опрос API и просто открытая вкладка — нет. Сигналы интерфейса отправляются не чаще раза в 15 секунд.

Удаляются пробные приглашения и сообщения с участием этих аккаунтов, связанные задания и оценки, подборки общей демокомпании и новые попытки тестирования общего кандидата. Восстанавливаются заполненные профили, публикация кандидата, исходные примеры тестов и подтверждённый уровень; демонстрационная привязка ФСП снимается. Идентификаторы аккаунтов и номер кандидата сохраняются. После долгого перерыва начните сценарий заново.

Обычные зарегистрированные аккаунты и самостоятельная история других пользователей не очищаются. Переписка другого пользователя с общим демоаккаунтом относится к пробной истории и удаляется вместе с ней. В демоаккаунтах используйте только вымышленные данные.

## Для эксплуатации

Механизм действует только при `DEMO_MODE=true` и только для точной пары `candidate@demo.example.org` / `employer@demo.example.org` с соответствующими ролями, признаком demo и без отдельного demo_run_id. Другие демонстрационные профили из банка не сбрасываются.

Миграция `e8f21021a001` добавляет таблицу `demo_workspace`. При первом включении сохраняются исходные завершённые примеры тестов и запускается новый час ожидания. Снимок не перезаписывается при входах и повторных сбросах. На публичном стенде сохранены три существовавшие демонстрационные попытки. На новой установке сохраняются примеры начального seed.

Планировщик `task-worker` проверяет срок вместе с обычной выдачей заданий. Сброс атомарный: при ошибке транзакция откатывается целиком. Общая блокировка сериализует сброс, активность двух аккаунтов и работу планировщика. Сессии остаются действующими; версия состояния меняется, устаревшие запросы интерфейса отклоняются, кабинет заново загружает данные. Открытый старый кабинет переходит на обзор.

Проверки на отдельной базе:

```bash
COOKIE_SECURE=false .venv/bin/python scripts/run_local.py .venv/bin/pytest -q tests/test_demo_idle.py
npm run build --prefix apps/web
.venv/bin/python scripts/run_local.py .venv/bin/python tests/browser_demo_idle.py
```

Обе проверки используют отдельные тестовые базы; время бездействия сдвигается только в них. Публичные аккаунты для проверки не очищаются принудительно.
