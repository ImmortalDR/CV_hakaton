# Почтовая интеграция и проверка доставки

Конфигурация актуализирована 21 октября 2026. Результаты реального IMAP-прогона ниже относятся к 11 октября. На публичном HTTPS-стенде настроен Gmail SMTP.
Реальная регистрация проверена для кандидата и работодателя: письмо отправлено,
получено в контролируемом ящике через IMAP, ссылка открыта в браузере,
адрес подтверждён, вход успешен. Неподтверждённый адрес не допускается к входу;
повторное использование ссылки отклоняется. Пароль и адрес оператора не публикуются.

## Настройка

Конфигурация находится только в закрытом .env, права 0600:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_TLS=true
SMTP_USER=YOUR_CONTROLLED_ADDRESS@gmail.com
SMTP_FROM=YOUR_CONTROLLED_ADDRESS@gmail.com
SMTP_PASSWORD=APP_PASSWORD_WITHOUT_SPACES
PUBLIC_URL=https://YOUR_PUBLIC_HOST
COOKIE_SECURE=true
```

Нужен пароль приложения Google, не пароль входа в аккаунт. Настройки Gmail
сверены с [официальной справкой](https://support.google.com/mail/answer/7104828?hl=en).
STARTTLS использует ssl.create_default_context: проверяется доверенная цепочка
и имя сервера. При невозможности TLS отправка прекращается; автоматического
перехода на незашифрованную аутентификацию нет при SMTP_TLS=true.

Если SMTP_HOST задан, настоящая доставка работает даже при DEMO_MODE=true,
когда демонстрационные профили/ФСП остаются доступны. Ответ регистрации содержит
delivery=smtp, demo_verification_url=null; verification-токен не возвращается.
Без SMTP_HOST демонстрация выдаёт ссылку локально; вне деморежима отсутствие
почты возвращает 503. После изменения .env необходимо пересоздать API:

```bash
docker compose up -d --no-deps --wait api
```

Не печатайте resolved Compose config, .env или SMTP debug-трассу в общий лог.
Не отправляйте тестовые письма случайным адресатам.

## Как проверялось

Скрипт scripts/check_mail_delivery.py запускается только по разрешению владельца
контролируемого Gmail-ящика. Он создаёт два уникальных plus-адреса этого же ящика
и две регистрации с вымышленными неопубликованными профилями. IMAP ищет только
эти сообщения и читает BODY.PEEK, не удаляя письма и не помечая их прочитанными.

```bash
.venv/bin/python scripts/run_local.py .venv/bin/python scripts/check_mail_delivery.py --base-url https://YOUR_PUBLIC_HOST --recipient YOUR_CONTROLLED_ADDRESS@gmail.com --out audit/mail-check
```

Проверяется UI-регистрация, отсутствие демонстрационной ссылки, запрет входа
до подтверждения, получение письма, открытие ссылки, удаление токена из URL,
одноразовость, вход и роль. Каждый запуск действительно отправляет до двух
писем и создаёт аккаунты; это не обычный unit-тест. Ошибка фиксируется как
этап и тип исключения без тела письма, адреса, токена и пароля.

Финальный реальный прогон: 2 отправленных / 2 полученных письма, обе роли pass.
Время от начала ожидания письма до завершения проверки входа: около 4,4 и
4,2 секунды; это не чистая задержка SMTP. Первый промежуточный прогон отправил
ещё одно письмо и подтвердил адрес, но остановился на UI-проверке. Его нельзя
выдавать за полностью успешный прогон. Сырые письма не публикуются.

Отдельно tests/test_mail.py проверяет обе конфигурации demo/non-demo и отказы
сертификата, авторизации, адресата, таймаут, неверный порт, отсутствующий пароль.
При сбое нет частично созданного аккаунта/токена/согласия: транзакция откатывается,
API возвращает 503 без технических секретов. Эти проверки используют заглушки
SMTP и не являются доказательством настоящей доставки. Autouse-фикстура удаляет
SMTP-настройки из окружения обычного pytest, предотвращая случайную отправку.

Браузерная регрессия browser_mail_navigation.py проверяет смену #verify после
загрузки приложения без полной перезагрузки и отказ повторного подтверждения.
Она запускается только на loopback-демостенде с имитацией почты.

## Границы и эксплуатация

- Проверен один Gmail-ящик с двумя адресами-алиасами, не два независимых провайдера.
- SPF/DKIM/DMARC pass не обнаружены в прочитанных Authentication-Results; их
  независимая проверка и настройка своего домена не заявляются выполненными.
- Получение в Gmail не гарантирует доставку другим провайдерам, отсутствие спама,
  отсутствие квот и бесперебойность Gmail.
- Повторная отправка подтверждения и восстановление пароля реализованы. Срок и одноразовость токенов проверяет сервер; новая отправка и сброс ограничены по частоте. Последняя проверка форм с имитацией SMTP описана в [ручной приёмке](HUMAN_ACCEPTANCE_2026-10-21.md).
- Отправка синхронная, таймаут 10 секунд. Нет очереди/outbox, автоматических
  повторов и панели доставки. Если сервер принял письмо, а ответ SMTP потерян,
  возможен откат регистрации при фактически доставленном письме. Это известная
  граница; надёжная очередь и согласованный outbox — отдельная доработка.
- Ограничитель регистрации локален процессу и не заменяет полноценную защиту
  почтового сервиса от злоупотреблений. Массовая почтовая нагрузка не проверялась.
- Подтверждение адреса не удостоверяет личность и не сертифицирует навыки.
