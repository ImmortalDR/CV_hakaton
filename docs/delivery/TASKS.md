# Адресные регулярные задания E09

Релиз 2026-10-11-modernization реализует адресный вариант дополнительного
пункта E09/VS.5. Это задания конкретной компании конкретному кандидату,
а не массовые соревнования категории и не автоматическая пересдача грейда.

## Выдача и доступ

Точка входа — вкладка «Задания от компаний» в обоих кабинетах. Работодатель
может предложить план только опубликованному кандидату, принявшему его
приглашение: требуется действующий ContactGrant. Одного появления в подборе
недостаточно. Кандидат отдельно включает выдачу после просмотра условий.

Работодатель задаёт название, текст, критерии ручной оценки, период 1…365
дней и срок ответа не длиннее периода. Эти границы — решение MVP, не цитата
организаторов. У компании может быть один незакрытый план на кандидата.
Шаблон неизменяемый; для других условий нужен новый план и новое согласие.
Каждая выдача сохраняет копию текста, критериев и версии.

| План | Значение |
|---|---|
| awaiting | Предложен, согласия на регулярную выдачу ещё нет |
| active | Кандидат включил выдачу |
| paused | Кандидат приостановил либо отозвал публикацию |
| closed | Окончательно закрыт любой стороной |

При включении первое задание выдаётся сразу. Worker проверяет планы каждые
60 секунд. Следующая выдача наступает не ранее указанной даты и только после
завершения предыдущего задания: ожидающий проверки ответ блокирует новую
выдачу. После простоя выдаётся максимум одно задание без накопленной очереди.
При возобновлении новый отсчёт начинается с текущего момента. План повторяет
тот же шаблон, автоматически новые тексты не генерируются.

## Ответ, проверка и приватность

Кандидат отправляет текст до серверного срока. После отправки редактирования
нет. Работодатель вручную ставит 0…100 и комментарий; повтор одинакового
запроса безопасен, изменение уже сохранённой оценки отвергается. Просроченное
задание не принимает ответ. Пауза/закрытие отменяет ещё не сданные задания;
уже сданное можно оценить при действующем доступе. Пропуск не понижает грейд.

Вкладка и счётчик обновляются каждые 30 секунд. Кандидат видит предложения и
ожидающие ответа задания, работодатель — ответы на проверку. Это уведомления
в приложении; почтовая доставка не подключалась. Дата последней проверки
показывается отдельно, без присвоения подтверждённого навыка или изменения
формулы ранжирования. Другие компании не получают ответы и оценки.

Отзыв публикации/обработки приостанавливает планы, отменяет открытые задания
и скрывает ответы от компании. Повторная публикация не возвращает прежнее
право на контакты и не включает выдачу автоматически. Собственная история
кандидата сохраняется. Скачанное/прочитанное ранее невозможно отозвать.

## Проверки и границы

tests/test_employer_tasks.py проверяет полный цикл, две компании/кандидатов,
отзыв, неизменность грейда, конкурентные worker/отправки, сроки, идемпотентность,
паузу и отсутствие пачки после простоя. tests/browser_tasks.py проходит согласие,
ответ, оценку и отзыв через UI; подготовка аккаунтов/приглашения идёт через API.
Мобильные ширины 360/390/768 px проверены в Chromium.

Нет автоматической оценки свободного текста, вложений, ротации шаблонов,
редактирования выданного задания, пагинации большой истории и отдельной
панели мониторинга worker. Ручная оценка работодателя сама по себе не является
независимой сертификацией профессионального уровня.
