# Запуск и сопровождение

Инструкции установки — в корневом README. Runtime: Python 3.12,
FastAPI 0.142.3, Starlette 1.3.1, SQLAlchemy 2.0.41, Psycopg 3.2.9,
Alembic 1.16.1, Uvicorn 0.34.3, Argon2-cffi 23.1.0, ReportLab 4.4.1;
React 19.1.0, TypeScript 5.8.3, Vite 6.4.4, Lucide 0.511.0;
PostgreSQL 16, Nginx 1.28. Точные транзитивные версии/хеши Python и версии
npm закреплены в lock-файлах. Базовые Python/Node/Nginx image tags могут
получать исправления upstream; PostgreSQL образ закреплён digest.

Сборка выполняется без параллельного запуска двух frontend-сборок на
маленьком сервере. Для ограничения памяти используются точечные импорты
иконок и отключён рекурсивный Rollup tree-shaking; esbuild сохраняет
минификацию. Это осознанная настройка, проверенная реальной сборкой.

## Данные и резервирование

Миграции выполняются перед стартом API. Additive seed работает только при
DEMO_MODE=true, не перезаписывает существующие аккаунты/попытки. Автоматической
очистки демонстрации нет. После прохождения общего аккаунта используйте новую
синтетическую регистрацию, а не удаление тома и не обход серверного кулдауна.

Резервная копия только своего проекта:

```bash
mkdir -p local-backups
docker compose exec -T db pg_dump -U fsp -d fsp -Fc > local-backups/fsp.dump
```

Копия содержит персональные данные, если оператор допустил их ввод; хранить
в закрытом месте вне git. Восстановление сначала проверять в отдельной пустой
БД этого же проекта. Не применять глобальные Docker prune/down -v для
обновления приложения. Для остановки достаточно `docker compose stop`.

## Переход из демонстрации

Для реальной доставки нужны SMTP_HOST/PORT/FROM, при необходимости USER/PASSWORD,
SMTP_TLS=true и DEMO_MODE=false. При отсутствии доставки регистрация
откатывается и возвращает 503, токен не показывается. При рабочем SMTP в
ответе нет демонстрационной ссылки. Реальная отправка в этой сдаче не запускалась.

Для публичного демостенда настроен отдельный Caddy в профиле `https`,
PUBLIC_URL=https://85-137-26-131.sslip.io и COOKIE_SECURE=true. Вход — через порты
80/443; HTTP перенаправляется на HTTPS. Внутренний порт 3080 и БД остаются
на loopback. Сертификат Let's Encrypt автоматически продлевает Caddy;
[конфигурация и проверки](HTTPS.md). Приложение не заявлено как готовое
производственное решение для персональных данных: нужны правила хранения,
удаления/запросов субъекта, юридические документы оператора и оценка размещения.
Наличие checkbox и журналов согласия не является заявлением о полной
юридической сертификации. UI-проверки используют вымышленные профили.
Отдельный исследовательский контур V4 использует реальные исторические тексты
CV; они не импортированы в публичную БД сервиса и не публикуются в GitHub.

Пароли, cookie, verification-токены, содержимое CV и `.env` не публикуются
в репозитории. Access log Uvicorn выключен. Email token передаётся во
фрагменте URL и удаляется frontend из адресной строки перед подтверждением.

## Ограничения эксплуатации

- Rate limit локален одному процессу; за Nginx в текущей конфигурации он
  делится клиентами одного proxy. Для публичного потока нужен limiter на
  доверенном внешнем адресе / общий backend и отдельная политика демовхода.
- Банк/подбор используют небольшую выборку без пагинации и оптимизации всех
  N+1 запросов. Замер относится к десяткам одновременных запросов и текущему
  демонабору; не к миллионам резюме.
- Нет восстановления пароля, повторной отправки письма, удаления аккаунта,
  UI управления сотрудниками, модерации работодателей, уведомлений по почте.
- Сессии/токены с истёкшим сроком отвергаются, но их фоновая очистка отложена.
- Нет реальной ФСП/OIDC-интеграции, прокторинга, импортов файлов и семантического
  поиска. ФСП-адаптер и план замены описаны отдельно.
- Общий демовход предназначен только для вымышленных данных; его нельзя
  оставлять включённым в среде реальных кандидатов.

Материалы исходного архива сохранены. Полное трёхпроходное чтение всех его
файлов не завершено. Автоматические хеши/сканы и содержательное чтение
разделены в `docs/review`; разрешение перейти к коду не меняет эти статусы.

## Установка и обновление текущей версии

Для новой установки: Docker Engine/Compose v2, Python 3; команды из корня checkout:

```bash
git clone --branch codex/modernization-20261011 https://github.com/ImmortalDR/CV_hakaton.git
cd CV_hakaton
python3 scripts/configure.py
docker compose up -d --build --wait
curl --fail http://127.0.0.1:3080/api/health
```

configure.py создаёт только отсутствующий .env с правами 0600. Существующий
пароль БД менять при обычном обновлении нельзя. По умолчанию веб-порт 3080
и PostgreSQL 5547 доступны только через loopback. Для удалённого просмотра:
ssh -L 3080:127.0.0.1:3080 USER@SERVER, затем http://localhost:3080.

На действующем сервере код исправлений развёрнут из отдельного worktree
/root/hakaton-fixes-20261011. Исходный /root/hakaton содержит незакоммиченные
материалы команды: их нельзя заменять checkout/reset. Перед обновлением
проверьте git status, выбранную ветку и существующий Compose-проект fsp-mvp.
После получения совместимой версии, сохранения дампа и проверки миграций:

```bash
docker compose build api web task-worker
docker compose up -d --no-deps --wait api web task-worker
curl --fail https://85-137-26-131.sslip.io/api/health
docker compose ps
docker compose logs --tail=80 api web
```

Модернизация добавляет миграцию b9e1c4d7a201 с двумя таблицами заданий.
Существующие попытки и данные не переписываются. У других обновлений совместимость
схемы нужно проверять отдельно. Откат образов безопасен только при совместимой
БД; сначала проверьте восстановление дампа в отдельной тестовой базе.

Перед исправлениями сохранён дамп local-backups/platform-fixes-20261011/
fsp-before.dump в исходном рабочем каталоге, читаемость проверена pg_restore.
Предыдущие образы сохранены под тегами before-platform-fixes-20261011
для fsp-mvp-api и fsp-mvp-web. Эти локальные артефакты не входят в GitHub.

Для HTTPS используйте существующий профиль https и настройки из HTTPS.md:
PUBLIC_URL, COOKIE_SECURE=true, HTTPS_HOST, HTTPS_SITE_ADDRESSES и ACME_DIRECTORY.
Секреты не копируйте в логи. Здоровье Caddy, срок сертификата и внешний HTTP-запрос
проверяются отдельно: успешный API health не доказывает исправность каждой пробы.
Обновление документации само по себе не требует перезапуска приложения.

## Воспроизводимая приёмка и восстановление

```bash
.venv/bin/python scripts/acceptance.py --base-url http://127.0.0.1:3080 --out audit/acceptance
.venv/bin/python scripts/verify_release.py --project fsp-verify-new --port 3084 --out audit/clean-new
```

Приёмка требует dev-зависимости, Chromium и отдельную fsp_test для backend.
Браузерные сценарии работают только на демостенде и создают вымышленные
аккаунты, затем снимают публикацию своего кандидата. --skip-backend позволяет
отдельно проверить удалённый стенд; отчёт явно укажет пропуск backend.

verify_release допускает только новый проект с префиксом fsp-verify-,
создаёт независимый пароль и том. Выполняет сборку, миграции, проверку
схемы, повтор seed, pg_dump/restore в отдельную БД, сравнение хешей всех
16 таблиц, перезапуск API/web/worker и HTTP-проверку. Секретный compose, env
и дамп остаются в audit с правами 0600; публикуется только result.json.
Команда оставляет стенд и том для расследования. Остановите именно его:

```bash
docker compose -p fsp-verify-new -f audit/clean-new/compose.json stop
```

Worker выдаёт задания с точностью до периода опроса (60 секунд), если БД
доступна. При сбое он пишет тип ошибки и повторяет цикл; проверяйте logs
task-worker. Сам статус Running не доказывает своевременную выдачу. При
обновлении с предыдущей версии сохраните дамп и образы; не запускайте
downgrade таблиц заданий после начала их использования.

Коллеги независимо подключили SMTP во время модернизации. Сохранено правило:
если SMTP_HOST задан, регистрация использует настоящую доставку даже при
DEMO_MODE=true; демоссылка в этом случае не возвращается. Без SMTP_HOST
демоссылка доступна только в деморежиме, иначе 503. Модернизация не проверяла
внешнюю доставку и не меняла почтовые секреты. Поэтому acceptance запускать
на отдельном демостенде с пустым SMTP_HOST, а не на публичном сайте с почтой.

Проверка публичного сайта без регистрации и отправки писем:

```bash
.venv/bin/python scripts/acceptance.py --read-only --skip-backend --base-url https://85-137-26-131.sslip.io --out audit/public-smoke
```

Нужны доступные общие демовходы; режим не меняет профиль/задания. Caddy теперь
запускается с init и GET-пробой /api/health. После наблюдавшегося накопления
процессов проверяйте docker stats и healthcheck; долгосрочная стабильность
требует наблюдения, краткий успешный прогон её не доказывает.
