## 0. Как пользоваться (30 секунд)

- Ставьте у каждого шага: PASS / FAIL / SKIP; рядом причину и путь/ссылку на снимок экрана без контактов.
- FAIL по must (★) = нельзя отправлять Pck5. SKIP по must также не закрывает проверку.
- Не чините сами в этой сессии — только фиксируйте; баг верните команде.
- Review-логины и пароли только из [FOR_JURY](FOR_JURY.md); свои данные не вводить.
- Q3/Pck4 подтверждены свежим API/UI-прогоном. Итерация 1 выявила остаток Q5/U01; следите за актуальной матрицей.
- План: доступ/упаковка 4 мин, must 8 мин, UX/планы 8 мин, регрессии 8 мин, итог 3 мин.
  Маршрут H-Pck2-walk идёт одновременно с остальными шагами, не повторяйте его второй раз.
- Откройте три отдельных профиля браузера, чтобы не смешивать роли.
  **К** = кандидат, login review.candidate.fsp@example.org;
  **Р** = работодатель, login review.employer.fsp@example.org;
  **Д** = другая компания, login review.employer2.fsp@example.org.
  Ниже каждый код роли означает этот точный логин; пароли берите по ссылке FOR_JURY.
- Все клики приложения выполняются на URL стенда выше. Документы пока можно читать локально
  по ссылкам из этого протокола; публичные GitHub-ссылки проверяются отдельно в H-PUSH.
- Перед изменениями запишите текущую публикацию и демо-ФСП К; после проверки восстановите их.
  Отозванное адресное согласие автоматически не восстановится — если оно нужно, примите новое приглашение.
- Если общий аккаунт занят или тест недоступен из-за пересдачи, поставьте SKIP и время доступности.
  Не сбрасывайте историю, не используйте настоящую почту ради обхода. Команда должна предоставить
  свободный демо-аккаунт и записать его логин в FOR_JURY; до этого соответствующий must не закрыт.
- Q1–Q3 делайте в одной активной попытке, не подтверждайте финальную сдачу без необходимости.
  Правило SQL проверяется только в новой выдаче; старый результат 90.62 не является проверкой исправления.
