## 0. Как пользоваться (30 секунд)

- Ставьте у каждого шага: PASS / FAIL / SKIP; записывайте краткий факт и время. Пустая клетка не означает PASS.
- FAIL по must (помечены ★) = нельзя отправлять Pck5. SKIP по ★ также оставляет допуск незакрытым.
- Не чините сами в этой сессии — только фиксируйте; баг верните команде.
- Review-логины и пароли только из [FOR_JURY](FOR_JURY.md); свои данные не вводить.
- Сейчас отправка заблокирована: Pck1 FAIL (противоречивый changelog), Pck2 PARTIAL (нет push), Q4 PARTIAL (статичная надпись «навыки подтверждены» до теста). Человеческая подпись не устраняет эти дефекты автоматически.
- Основной маршрут: 25–40 минут. Три отдельные браузерные сессии для кандидата и двух компаний. Сначала тест и обзор, затем приглашения/доступ, затем упаковка. Общие шаги выполняйте один раз, результат переносите в связанные клетки.
- Если общий аккаунт уже израсходовал попытку, запишите SKIP и видимый срок; запросите у команды подготовленный демонстрационный аккаунт. Не сбрасывайте данные и не считайте регистрацию проверенной почтой.
- Для документационных шагов открывайте ссылки через [FOR_JURY](FOR_JURY.md) и [SUBMISSION_LINKS](SUBMISSION_LINKS.md). Пока push отсутствует, GitHub может показывать старые файлы — это блокер H-PUSH.
