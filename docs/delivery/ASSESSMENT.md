# Банк и рубрика 2.0.0

Восемь числовых заданий за 30 минут: четыре семейства, два варианта каждого.
Четыре вопроса проверяют основной навык Python/SQL, четыре — вспомогательный.
Проходной результат: **не менее 6/8 и не менее 3/4 по основному навыку**.
Для любого навыка met означает не менее 75% верных ответов по этому навыку.
Баллы не округляются вниз: 7/8 = 87,5%. Неудача сохраняет прежний грейд.

| Категория | Основные семейства | Вспомогательные семейства |
|---|---|---|
| Python Junior | фильтрация и сумма; накопление с индексами | включённые границы; поиск дефекта abs |
| Python Middle | общие ссылки списков; изменяемый аргумент по умолчанию | идемпотентность; фиксированные окна лимита API |
| Python Senior | зависимости задач; поведение LRU-кеша | backoff; ограниченные повторы по кодам ответа |
| Data Junior | WHERE/SUM; NULL/COALESCE | медиана; среднее после удаления ошибочного замера |
| Data Middle | LEFT JOIN; GROUP BY/HAVING | взвешенная доля; условная конверсия |
| Data Senior | DENSE_RANK; оконная сумма по группе | потерянное обновление; оптимистическая блокировка |

Итого 24 семейства. Порядок воспроизводимо перемешивается; в семействе меняются
числа/входы, сохраняются тип операций и структура. Исходные формулы — bank.py,
отдельные решения — evaluation/oracles.py (исполнение SQL в SQLite, реальный
functools.lru_cache, семантика Python, альтернативные вычисления).

Сервер сохраняет seed, версию, весь текст, параметры, эталоны и результат.
Клиент получает только текст/навык/id до завершения; балл и ключи задаёт сервер.
Перед ответом проверяется, что номер вопроса входит в сохранённую попытку.
Одинаковая завершённая попытка повторно не оценивается. SHA-256 набора уникален
в БД; генератор пробует до 20 новых seed. Ответы проверяются через Decimal,
запятая допускается, NaN/Infinity/пустые ответы не засчитываются, допуск 0,005.

## Совместимость

- 1.0.0/1.1.0: четыре вопроса, общий порог 75%.
- 1.2.0: четыре вопроса, 75% и 2/2 по основному навыку.
- 2.0.0: восемь вопросов, 75% и 3/4 по основному навыку.

Старые активные попытки оцениваются по собственной версии; их вопросы не
генерируются заново. Генератор воспроизводит 1.1.0 и 1.2.0, это проверено
замороженными fingerprint исходных релизов. Для 1.0.0 используется сохранённый
набор; заново генерировать его этот код не обещает. Интерфейс получает рубрику
каждой попытки от сервера, включая исторические.

Первый провал не присваивает низкий грейд. Тест ниже можно выбрать добровольно.
Пересдача той же пары категория/грейд — через 24 часа от старта; смена уже
подтверждённого грейда — через 90 дней после успешной смены. Повторное
подтверждение того же грейда не сдвигает дату. В один момент одна активная
попытка. Истечение срока не меняет грейд. Переход специализации после первого
подтверждения в MVP не поддерживается.

## Измерения и границы

[Сравнение версий](../../evaluation/bank_v2_results.json): 42000 симулированных
попыток, 36000 независимых сверок ответов, расхождений 0. Частые ответы семейства
выбирались только на 200 dev-вариантах; проверялись на других 500 вариантах
каждой категории. В 2.0.0 успехов угадывания 0/3000, в 1.2.0 — 75/3000.
Ноль не означает невозможность угадывания: 95% верхняя граница Wilson при
0/500 — около 0,76% для одной категории в данной синтетической модели.

При независимой вероятности ошибки 20% на вопрос средняя доля успеха выросла
с 59,33% до 71,4%, попарное совпадение исходов — с 51,67% до 59,14%.
Это поведение модели, а не наблюдения людей. Все семьи узнаваемы: заучивание
метода решения, внешняя помощь и LLM остаются возможными. Docker/React не
проверяются этим банком. Восемь числовых заданий не доказывают профессиональный
грейд и не охватывают всю работу Senior.

Порог и длительность — решения команды до измерения, а не эмпирическая
калибровка. Следующий этап — содержательное экспертное ревью и реальный пилот:
[инструкция и инструменты](HUMAN_PILOT.md). Участников и независимых человеческих
меток пока 0, такие результаты помечены not_run.
