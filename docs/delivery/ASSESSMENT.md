# Банк и рубрика

Версия банка **1.2.0**, два направления и три уровня. 12 собственных семейств,
в каждой попытке два варианта каждого из двух семейств категории: четыре
числовых ответа за 30 минут. Один верный ответ — 25 баллов, подтверждение
выбранного грейда — от 75 и оба верных ответа по основному навыку Python/SQL. Навык считается met при не менее 75% ответов
своего семейства; при двух вопросах это 2/2. Успешный новый тест с 3/4 поэтому может
оставить вспомогательный навык unmet, но основной навык обязан быть met. Это видно работодателю отдельно от общего грейда.

| Категория | Семейства | Что проверяется |
|---|---|---|
| Python Junior | py_filter, py_boundary | фильтрация/сумма; ошибки включения границ |
| Python Middle | py_alias, http_keys | общие ссылки вложенных списков; идемпотентность |
| Python Senior | py_dag, http_backoff | зависимости параллельных задач; время повторов API |
| Data Junior | sql_where, stats_median | фильтр/агрегация; медиана |
| Data Middle | sql_join, stats_weighted | отсутствие связей при LEFT JOIN; взвешенная конверсия |
| Data Senior | sql_rank, tx_snapshot | плотный ранг; потерянное обновление |

Параметры: a=2…9, b=2…8; основной список — семь чисел 1…20. Граничные
входы выбираются из a−2…a+b+2 с возможными повторами. Для DAG c=2…12;
повторы HTTP — 3…5 попыток; восемь идемпотентных запросов из четырёх ключей;
шесть заказов с customer_id из 1…4 при пяти клиентах. Точные генераторы,
эталонные формулы и объяснения находятся в `apps/api/fsp/bank.py`.

Используется отдельный `random.Random(seed)`, версия и полный вариант
сохраняются в PostgreSQL. SHA-256 текста набора уникален в БД; генератор
пробует до 20 новых seed при совпадении. Клиент не выбирает seed и не присылает
оценку. До завершения в API только текст и навык. После завершения доступны
правильные ответы и объяснения; повторная сдача сохраняет первый результат.

Ответ обрабатывается Decimal; поддерживаются точка/запятая, пробелы вокруг
числа. Допуск 0,005 для округления. NaN, Infinity, пустые и нечисловые ответы
не засчитываются. Генерация не использует LLM в runtime и не запускает
пользовательский код. Набор `evaluation/oracles.py` отдельно решает задачи:
SQL выполняется в памяти, Python-семантика и расписания моделируются пошагово.

## История и изменения уровня

Первый неуспешный тест не присваивает грейд. Можно сразу самостоятельно
выбрать другой, в том числе более низкий уровень. Пересдача той же пары
специализация/уровень — через 24 часа от старта последней попытки.
После подтверждения смена грейда, включая добровольное понижение,
возможна через 90 дней от последней успешной смены. Тест того же уровня
разрешён с отдельным интервалом 24 часа. Границы включённые: ровно 24 часа
или 90 дней — разрешено. Повторное успешное подтверждение того же грейда
не сдвигает дату смены. Провал и истечение времени сохраняют прежний грейд.

В один момент у пользователя одна активная попытка. При смене вкладки она
восстанавливается. До завершения попытки специализацию менять нельзя;
после первого подтверждения специализация в MVP закреплена. Переход на другую
специализацию после подтверждения пока не поддерживается.

## Границы выводов

Числовая параметризация затрудняет распространение конкретных ответов,
но решение семейства остаётся узнаваемым. Нет прокторинга и защиты от LLM,
подсказок другого человека или выученного алгоритма. Четыре задания не
покрывают все обязанности Junior/Middle/Senior. Названия уровней — рубрика
демонстрации, а не подтверждённый профессиональным сообществом стандарт.

Версия 1.1.0 исправляет постоянный ответ граничного семейства из черновой
1.0.0. Сохранённые ранние демопопытки остаются со своей версией и своим
эталоном. Они не перезаписываются при обновлении банка.

Фактические числа, матрица ошибок и ограничения оценки приведены в
`VALIDATION.md` и `evaluation/results.json`. Следующий необходимый шаг —
слепая оценка заданий профильными экспертами и пилот на людях с несколькими
вариантами, независимыми метками, анализом сложности и пограничных результатов.
