# Проверка сервиса и настоящей почты

База: 5f680dd, ветка codex/modernization-20261011. Пользователь разрешил проверку
SMTP и получение контрольных писем в принадлежащем ему Gmail-ящике. Пароль
совпал с уже настроенным; .env сохранён с правами 0600, секреты в git не внесены.
Ограничение времени — 20 минут. Работа выполнялась в отдельном существующем
worktree, чужие незакоммиченные материалы /root/hakaton не заменялись.

## Содержательное ревью

1. Повторно изучены SMTP-блок и транзакции регистрации, подтверждение/вход,
   жизненный цикл Auth и hash-ссылки, Compose/секреты, pytest-фикстуры,
   приёмочная команда, пользовательское руководство и матрица требований.
2. Прослежен путь UI → API → письмо → IMAP → ссылка → одноразовый токен →
   сессия; связаны реальные/демо-режимы, TLS, исключения и откат БД.
3. Сопоставлены сценарии приёмки и негативные случаи: неверный сертификат,
   SMTP-отказ/таймаут/конфигурация, отсутствие токена в API, повтор ссылки,
   роли, унаследованные настоящие SMTP-секреты в обычных автотестах.

Это целевой аудит действующего сервиса, не повторное полное чтение стороннего
архива. Параллельные автоматические проверки не засчитаны как чтение.

## Исправления

- Подтверждено в runtime Python: неявный SMTP-контекст имел CERT_NONE.
  Теперь STARTTLS использует проверку сертификата/имени через CERT_REQUIRED.
- Ошибки конфигурации порта/пароля и TLS обрабатываются с 503 и откатом.
  Date и Message-ID добавлены к письму, пользователю показано ясное сообщение.
- Подтверждение обрабатывает hashchange, а не только первоначальную загрузку.
  Токен удаляется из адресной строки; повтор отвергается сервером.
- Обычный pytest не наследует SMTP-окружение. Настоящая доставка вынесена
  в отдельную явно запускаемую команду с контролируемым адресом.

## Реально выполнено

92 backend-теста, 55 числительных, 18 сценариев требований, 11 проверок заданий,
регрессия почтовой навигации, публичный HTTPS smoke/OpenAPI, сборки API/web.
Основной путь: тест → результат → доказательства → подбор → приглашение с
зарплатой → принятие → контакты → диалог. Проверены две компании, отзыв,
закрытый/открытый PDF, мобильные размеры и исторические рубрики в backend.

Почта: SMTP-аутентификация и IMAP SSL; 2 письма финального прогона получены,
UI-подтверждение/вход обеих ролей, отказ неподтверждённому и повтору ссылки.
Промежуточный почтовый прогон завершился AssertionError после получения и
подтверждения; уточнена оснастка и явное переключение на вкладку входа.
Завершённым считается только последующий успешный прогон обеих ролей.

Нагрузка: отдельный стенд, 30 вымышленных сессий / 270 чтений / 12 профилей,
0 ошибок, p95 3379,96 мс. Выход load_probe направлен в audit, сами операции
не менялись. Runtime pip/npm audit: известных уязвимостей 0 на момент запроса.
Базы предупреждений не являются полной проверкой безопасности.

Новые изменения схемы не требовались. API/web обновлены, сервисы здоровы;
worker работает, Caddy не накапливает процессы в проверенном коротком окне.
Предыдущие результаты clean install/restore относятся к тому же домену и
миграции b9e1c4d7a201; они не переименованы в новую проверку восстановления.
