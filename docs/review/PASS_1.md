## Содержание изученных исходников

HireDesk: компоненты ui.tsx, оба dashboard, auth context, API wrapper,
ProtectedRoute, типы и форматирование; серверные User/Application,
контроллеры auth/applications, middleware auth/upload и JWT.
Рабочая модель — прямой отклик с job ownership, не обратное приглашение.
UI можно адаптировать под новый API; подтверждение email и согласия отсутствуют.
Company находится в User; требуется самостоятельная сущность организации.

ATS: scoring.py прочитан целиком. Извлечение навыка из резюме и confidence
не доказывают квалификацию. При unknown стаже skill-matched criterion
остаётся met; max(minimums)=0 вызывает деление на ноль; TOKEN_PATTERN
не понимает кириллицу. Дефекты проверяются отдельно от полного запуска.

PrairieLearn: примеры calculated и additionalNames разделяют параметры
варианта и серверные correct_answers. question_phases.py исполняет
доверенные контроллеры заданий и проверяет допустимые изменения data.
В MVP нужен собственный небольшой банк, без исполнения кода кандидата.
Параметризация сама по себе не доказывает равенство сложности.

OpenResume: index.ts явно ограничивает парсер одноколоночными английскими
резюме. Ручной профиль соответствует ТЗ и устраняет зависимость от OCR.

Оба Kaggle notebook прочитаны: все ячейки, зависимости и доступные outputs.
В darysha TF-IDF и TargetEncoder fit предшествуют split, idCv удалён до
группировки, test используется для early stopping и выбора порога.
В siddigantm get_embeddings не видит локальные model/device из main;
result_df.loc[i+j] допускает коллизии; очистка выбрасывает русский текст.
Сохранённые заявления README о качестве не являются нашими метриками.
