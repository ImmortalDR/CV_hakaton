# ФСП · платформа обратного найма

**Состояние после ручной приёмки:** [сверка утреннего плана](docs/delivery/CURRENT_STATUS_2026-10-21.md), [приёмка и исправления](docs/delivery/HUMAN_ACCEPTANCE_2026-10-21.md), [оставшиеся действия](docs/delivery/REMAINING_AFTER_FINAL_AUDIT_2026-10-21.md). Прикладной код `c4bca3c`; актуальные изменения локально и на стенде, push отложен пользователем.

**Материалы этапа A (21.10.2026): [маршрут для жюри](docs/delivery/FOR_JURY.md), [changelog](docs/delivery/CHANGELOG_STAGE_A.md).**

Работающий MVP: кандидат подтверждает навыки тестом, работодатель получает
объяснимую подборку и отправляет личное предложение с зарплатой в рублях.
Контакты открываются только пригласившей компании после принятия кандидатом.

**Демонстрационный режим:** все примеры вымышлены. Без настроенного SMTP подтверждение почты
имитируется отдельной кнопкой; при настроенном SMTP отправляется письмо; достижения ФСП получены от демонстрационного
провайдера. Не вводите реальные персональные данные в общие демоаккаунты.

## Запуск

Нужны Docker Engine с Compose v2 и Python 3 для создания конфигурации.
Рабочая ветка: `codex/fsp-mvp`.

```bash
git clone --branch codex/fsp-mvp https://github.com/ImmortalDR/CV_hakaton.git
cd CV_hakaton
python3 scripts/configure.py
docker compose up -d --build --wait
curl --fail http://127.0.0.1:3080/api/health
```

Откройте **http://localhost:3080**. Кнопки «Я кандидат» и «Я работодатель»
дают доступ к общим примерам. Для полного сценария зарегистрируйте собственные
вымышленные аккаунты двух ролей. Тесты изолированы от демонстрационной БД.
Обычный запуск добавляет недостающие примеры, сохраняя существующие записи. Повторная отправка письма и восстановление пароля требуют настроенного SMTP; демонстрационных ссылок восстановления API не выдаёт.

По умолчанию сервер слушает только loopback. Для удалённого просмотра используйте SSH-туннель:
`ssh -L 3080:127.0.0.1:3080 USER@SERVER`, затем тот же локальный адрес.

Публичный демостенд: **https://85-137-26-131.sslip.io/** (стандартный порт 443).
HTTP на порту 80 перенаправляется на HTTPS. Внешний порт 3080 больше не нужен.
Прежний адрес `https://85.137.26.131/` перенаправляется на домен.
[Настройка HTTPS и фактические проверки](docs/delivery/HTTPS.md).

```bash
docker compose ps
docker compose logs --tail=80 api
docker compose restart
docker compose stop
```

Compose-проект `fsp-mvp`, том `fsp-mvp_fsp_db`. Не удаляйте том ради перезапуска.
Другие проекты сервера не участвуют в запуске. `.env` создаётся с новым паролем
БД и правами `0600`; существующая конфигурация не перезаписывается.

## Реализовано

- Кабинеты кандидата и работодателя, регистрация, одноразовое подтверждение
  e-mail, повторная отправка письма, восстановление пароля, сессии, компания и ручной профиль с PDF на русском языке. При регистрации и смене пароля — повтор ввода и кнопки показа.
- Python / бэкенд и аналитика / SQL, Junior–Senior, 24 семейства задач,
  воспроизводимые варианты и серверная проверка. Неудача не понижает грейд.
- Банк и структурированная потребность, группировка по категории,
  доказательства `met / unmet / unknown`, история подборок.
- Приглашение без вакансии, обязательная положительная вилка RUB,
  согласованные статусы и адресное раскрытие контактов, внутренний диалог.
- Адресные задания работодателя: отдельное согласие, периодическая выдача, ответ и оценка, пауза/возобновление. Оценка компании не изменяет грейд.
- Отзыв публикации закрывает выдачу, PDF и диалог. Повторная публикация
  не восстанавливает прежнее разрешение на контакты автоматически.

Свободное описание потребности сохраняется. Для ранжирования используются
явно выбранные и подтверждённые структурированные поля; автоматического
понимания произвольного текста и внешнего поиска вакансий нет.

## Проверки и измерения

**Последние проверки:** 119 серверных тестов, 8 проверок регистрации/восстановления с имитацией SMTP и 24 группы живого HTTPS smoke — PASS. Ручной маршрут пройден на компьютере и Android; ограничения доказательств — в текущем статусе.

[Фактический отчёт](docs/delivery/VALIDATION.md),
[матрица приёмки](docs/delivery/REQUIREMENTS_STATUS.md),
[результаты синтетической оценки](evaluation/results.json),
[проверка актуальных документов](docs/delivery/documentation-checks.json).

Проверка экспорта: `.venv/bin/python scripts/check_current_docs.py --rendered-docx /путь/к/pdf-из-docx`. Предварительно преобразуйте три DOCX из `docs/delivery` (FSP_MVP, FINAL_REPORT_2026-10-21, STAGE_A) в PDF через LibreOffice в отдельный каталог. Проверка не запускает тесты приложения повторно. Старый `scripts/check_delivery.py` относится к комплекту 7 октября.

Matching-1.2.0: веса 30/15/45/10 выбраны на отдельном dev (16 профилей / 2 запроса). На неизменённом holdout (48 профилей / 8 запросов) P@5 **0,80 до и после**; исторический baseline **0,475**. Рост P@5 не доказан. Знаменатель всегда 5. Это авторские сценарии без внешних
экспертов; профессиональная валидность грейдов на людях не доказана.

Дополнительный [оценочный датасет 1.0.0](dataset/README.md) включает 480
размеченных контрольных пар, 480 симулированных попыток и отдельное локальное
дополнение из открытых источников. [Архив и результаты](dataset/published/README.md)
содержат ссылки на источники, схемы, SHA-256 и офлайн-проверку. Новая выборка
включает запросы без подходящих кандидатов и с неизвестными навыками; её метрики
не сравниваются напрямую с приведёнными выше 0,80. Разметчиков и внешней
сертификации нет; импорт выполняется в отдельную оценочную БД.

Локальная среда для разработки и воспроизведения проверок: Python 3.12,
Node 22 (локальная сборка также проверена на Node 18.19), PostgreSQL 16.
Нужны системные шрифты DejaVu Sans. Сначала запустите `docker compose up -d db`.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.lock
docker compose exec -T db createdb -U fsp fsp_test
COOKIE_SECURE=false python3 scripts/run_local.py .venv/bin/pytest -q tests
PYTHONPATH=apps/api:. .venv/bin/python -m evaluation.run
.venv/bin/playwright install --with-deps chromium
python3 scripts/run_local.py .venv/bin/python tests/browser_flow.py
python3 scripts/run_local.py .venv/bin/python tests/load_probe.py
```

`createdb` нужен один раз; сообщение «already exists» означает, что БД уже
подготовлена. Интеграционные тесты очищают **только БД с точным именем `fsp_test`**.
Браузерный тест добавляет два вымышленных аккаунта в работающую демонстрацию.
Он читает параметры заданий из локальной БД только для независимого эталонного
решателя; публичный API правильные ответы до завершения не выдаёт.

Для frontend: `cd apps/web`, `npm ci`, `npm run build`.
Для dev-режима остановите только сервисы `web api` этого Compose-проекта,
запустите API и frontend в отдельных терминалах:

```bash
python3 scripts/run_local.py .venv/bin/alembic -c apps/api/alembic.ini upgrade head
python3 scripts/run_local.py .venv/bin/python -m fsp.seed
python3 scripts/run_local.py .venv/bin/uvicorn fsp.main:app_factory --factory --host 127.0.0.1 --port 8007 --no-access-log
```

Затем в `apps/web`: `npm run dev`. Vite проксирует `/api` на порт 8007.

```bash
PYTHONPATH=apps/api:. .venv/bin/python -m evaluation.bank_v2_audit
PYTHONPATH=apps/api:. .venv/bin/python -m evaluation.pilot prepare --root audit/new-pilot
PYTHONPATH=apps/api:. .venv/bin/python -m evaluation.pilot evaluate --root audit/new-pilot
```

Первый скрипт не использует БД и внешние источники. Для пилота нужны реальные

банка 1.1.0 и 1.2.0 соответственно; их отчёты не описывают текущий банк 2.1.1.
