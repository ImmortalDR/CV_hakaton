# Проверки по задачам — Closed Contour

Для каждой задачи: что сделать агенту, что считать PASS, что отдать человеку.

---

## CC0 — рамка

- Есть `COMPREHENSIVE_…`, `BACKLOG_…json`, `00_START_HERE.md`.  
- В NOT TODO явно: air-gap, ФСТЭК, VPN-only продукт.  
- **PASS:** файлы + цитата NOT TODO в протоколе.

## CC1 — инвентарь деплоя

- Прочитать актуальный `compose.yaml`, `.env.example`, `scripts/configure.py`.  
- Таблица: сервис, image/build, порты (host bind!), env, volumes, health, restart.  
- Отметить: что уже «контурно» (например `127.0.0.1`, DEMO_MODE).  
- **PASS:** `01_INVENTORY.md` совпадает с файлами (выборочно 3 поля сверены `grep`/`sed` в протоколе).  
- **FAIL:** устаревший порт/сервис или «у нас k8s», которого нет.

## CC2 — карта данных

- Пройти модели/схемы кандидатов, работодателей, сообщений, PDF, логов.  
- Поля: ПДн / около-трудовые / технические.  
- **PASS:** `02_DATA_MAP.md` с ≥1 ссылкой на файл кода на каждую группу полей.  
- **HUMAN_ONLY:** «достаточно ли удаления для 152-ФЗ» — в человеческий протокол.

## CC3 — install runbook

- Шаги от чистой Ubuntu/Debian-подобной VM (или явно указанной ОС).  
- Prefetch: Docker, доступ наружу за deps.  
- Варианты A/B доступа.  
- Откат: down + удаление томов **только** своего проекта.  
- **PASS:** человек по runbook может повторить без Slack; агент сам прошёл шаги устно в dry-run (CC4).  
- **FAIL:** шаги требуют секретов из головы / пути только с хакатонного VPS.

## CC4 — dry-run

- Скрипт создаёт изолированный проект (имя `fsp-cc-dryrun` или project `-p`).  
- Не использует том/порт продакшен-стенда, если они заняты — выбрать свободные или SKIP с причиной.  
- **PASS:** лог в evidence, exit 0, health ok внутри dry-run, затем down.  
- **FAIL:** скрипт тронул `fsp_db` стенда или упал без лога.

## CC5 — секреты

- `.env` в `.gitignore`; `.env.example` без реальных паролей.  
- Документ: как генерировать (`configure.py`).  
- **PASS:** команда проверки «нет `.env` в git ls-files» в протоколе.  
- **FAIL:** в репо закоммичен секрет.

## CC6 — threat model

- ≥6 угроз с владельцем.  
- Не раздувать: лучше короткая правда.  
- **PASS:** каждая угроза имеет «есть/дыра».  
- **FAIL:** пустые строки или «защищены полностью» без механизма.

## CC7 — DDoS / edge

- Что в продукте (rate limit? нет?).  
- Что на edge заказчика.  
- **PASS или PARTIAL:** явный `not_implemented` список.  
- **FAIL:** «у нас антидодос» без кода.

## CC8 — hardening

- Чеклист ☐ с колонкой auto/human.  
- **PASS:** ≥8 пунктов; минимум 2 auto-проверки реально выполнены в протоколе.  

## CC9 — ПДн 152

- Роли on-prem vs SaaS.  
- Согласия (публикация, контакты).  
- Удаление / экспорт — факт по коду.  
- **PASS:** нет фразы «полностью соответствуем» без `LEGAL_REVIEW_NEEDED`.  
- **HUMAN_ONLY:** принятие юристом/Данилой.

## CC10 — ТД / граница

- Явно: не кадровый учёт.  
- **PASS:** список «не обещать на питче».

## CC11 — демо-политика

- DEMO_MODE + review accounts + запрет реальных ПДн на sslip.  
- **PASS:** согласовано с FOR_JURY или новым блоком.

## CC12 — onepager

- 1–2 экрана; ссылки на CC3/CC6/CC9.  
- **PASS:** читается без кода; не противоречит канону §0.  
- **HUMAN_ONLY:** «можно ли так говорить жюри» — галочка человека.

## CC13 — указатель из Stage A docs

- ≤1 короткий абзац + ссылка.  
- **PASS:** не дублирует Q1–Q7.

## CC14 — 90s питч

- Текст ≤190 слов.  
- **PARTIAL ok**, если must закрыты.

## CCV1 — матрица

- JSON по всем CC* + CCV*.  
- **PASS:** must без FAIL; evidence свежие.

## CCV2 — human protocol

- Заполненный шаблон с ☐.  
- **HUMAN_ONLY** до галочек человека.

## CCV3 — регрессия соседей

- `curl` health публичного стенда (если сеть есть).  
- Основной клон: нет нашего `reset --hard` в истории сессии.  
- **PASS:** health 200 или честный NOT_RUN с причиной; WIP соседей на месте.
