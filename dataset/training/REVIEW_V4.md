# Ревью V4: границы и реальные проверки

Объём поручения: первая командная задача, данные/модель/оценка. Приложение,
рабочая БД и защищённый проект intellect не менялись. Ветка codex/dataset-v4.
Прежний сторонний архив, интерфейс и материалы второй задачи не переаудированы.

## Три содержательных прохода

1. Назначение: прочитаны инструкции, карта workspace, протокол, схемы вакансий,
   CV, событий, прежние скрипты подготовки/обогащения/обучения и их отчёты.
   Все 17 вопросов/ответов оригинального XLSX повторно прочитаны через XML.
   Смысл ТЗ сверялся с полным извлечённым текстом и матрицей; повторного
   визуального просмотра PDF не было. Новый код просмотрен целиком; большие
   CSV разобраны потоково, что не объявляется ручным чтением каждой записи.
2. Интегральная цепочка: base SQLite read-only → отдельный индекс → полные
   проходы CV/событий/историй → явный ответ/четыре ID/30 дней → as-of тексты →
   legacy-граф → новый split → неразмеченный корпус без heldout → train-only
   признаки → сохранённый выбор → test → локальный интерфейс и архив.
   Для retrieval отдельно: фиксированный сэмпл людей → профиль на дату запроса
   → неизвестные исходы сохраняются unknown → полнота известных положительных.
3. Соответствие и логика: M05/M07 — нет грейдов/понижения; M15/M23 — отдельная
   оценка поиска и ранжирования, нет выдуманных отрицательных исходов; M20/M26 —
   нет записей в приложение/раскрытия контактов/публикации реальных текстов.
   Проверены повторные CV одного человека, даты историй, копии прежнего test,
   одинаковые баллы, одинаковая вакансия с разными снимками, пустая основная
   метрика, резервный критерий выбора, роли документов и целостность артефактов.

Покрытие новых файлов: review_v4_coverage.csv. Архитектурные решения и критерии
записаны до обучения в EXPERIMENT_V4.md и Git 2d9cdc8/fa717ae/7f1f23c.
Дополнительный retrieval-пул введён после просмотра только размеров split,
до model scores: в исходном test меньше 100 человек. Правила и ограничение
2 000 дополнительных людей зафиксированы до оценки этого пула.

## Найденное и исправленное до измерения

- Старый фильтр названия пропускал вакансии с IT-содержанием требований/обязанностей.
  Расширение остаётся эвристикой, не профессиональной разметкой.
- В ранжировании несколько CV одного человека давали бы несколько позиций.
  Оставляется первое непротиворечивое наблюдение человека для вакансии.
- Нельзя использовать для раннего retrieval обогащённый профиль, собранный
  на поздний отклик, даже если базовый CV опубликован раньше. В небольшом
  пуле проверяется дата восстановления; в расширенном история собирается as-of.
- Смешанные группы менее десяти человек не выдают основную NDCG@10.
- Нельзя объявить top-100 успешным поиском, если весь пул меньше 100; такие
  запросы посчитаны отдельно, подготовлен дополнительный нетривиальный пул.
- Первая проверка near-copy fixture не прошла: многократное повторение восьми
  слов не даёт длинного множества уникальных шинглов при binary hashing.
  Исправлен искусственный fixture на разнообразный текст; порог не ослаблялся.

## Что проверки не доказывают

Хеши — целостность, не подлинность событий/сертификация. Программные fixtures —
проверка конвейера, не экспертные метки. Исторический ответ на отклик не является
подтверждённым навыком или текущим наймом. Отсутствие пересечений с неизвестным
полным корпусом предобучения E5 не доказано. Случайный групповой split не
измеряет перенос на будущие годы. Результаты исполнения: RESULTS_V4.md и reports.

Первый запуск был остановлен прерыванием диалога во время кодирования train,
до сохранения первой матрицы эмбеддингов и до обучения/просмотра test scores.
Неполный каталог сохранён отдельно. До повторного запуска добавлен SQLite-кеш
эмбеддингов с фиксацией каждых 10 документов, привязкой к версии весов,
тексту, роли query/passage и параметрам pooling. Протокол и split неизменны.

Первый V4-CV завершился с кодом 137 до первого fold: обращение к NPZ-массиву
внутри цикла по строкам каждый раз распаковывало весь массив и сохраняло view
на отдельную копию. Исправлено на однократное чтение a/b и копии отдельных
векторов; регрессия ограничивает число распаковок двумя на файл. Неудачный
каталог/лог сохранены; параметры и разбиение дополнительной серии неизменны.
