# V3: профессиональная история и ранжирование кандидатов

Протокол 10 октября 2026, до нового обучения. Используем только существующие
trudvsem; DeepSeek, внешние LLM, загрузки новых корпусов и БД сервиса не используются.

**Цель:** записанное принятие/отказ в течение 30 дней в ответ на отклик.
Не трудоустройство, компетентность, грейд или причинный эффект рекомендации.
Прямые ссылки и четыре идентификатора проверяются как в V2; молчание — unknown.

Дополняем CV должностями, обязанностями и достижениями из workexp, специальностью,
квалификацией и факультетом из edu. Только публикации строго до создания отклика.
Работа не может начаться после публикации/отклика; ошибочные даты исключаются.
Образование с ошибкой года или окончанием в год отклика/позже исключается:
точного дня выпуска нет. Работодатели и учебные заведения используются только
для дедупликации записей, не как признаки. Стабильного ID записи стажа нет:
ключ место+должность+начало — приближение, неоднозначные версии исключаются.
Не складываем повторные версии стажа. Сохраняем номера всех использованных CSV-записей.
Проверяем восстановление пар, ранее потерянных из-за короткого CV, без ослабления дат.

Старые V2 split остаются якорями. Новые связанные компоненты учитывают человека,
CV, вакансию и точные копии как исходного, так и обогащённого текста. Компоненты,
соединяющие разные старые split, исключаются, а не переносятся между ними.
Исходные CV короче 30 символов (порог V2) — только названия ролей: их совпадение
не считается копией полного CV. Обогащённый документ проверяется полностью.
Неякорные компоненты распределяются стабильным хешем 70/15/15. Защита от близких
копий >=0.95 применяется к обеим версиям текста. Общий набор используется для
парного сравнения исходного и обогащённого представления.
Test уже изучался в V1/V2: все новые результаты исследовательские, не внешняя
слепая валидация. Новые только в V3 пары отмечаются отдельным описательным срезом.

Заранее ограниченная серия на CPU:

- исходная word TF-IDF регрессия V2 на старом/обогащённом тексте;
- word+char TF-IDF взаимодействия: слова 1–2, char_wb 3–5 для русских форм слов;
- компактные признаки текстового соответствия и покрытия технологий,
  регуляризованная регрессия и неглубокий histogram gradient boosting;
- pairwise logistic ranker: разности признаков принятого/отклонённого кандидата
  **одной вакансии с одинаковым текстом**, одинаковый суммарный вес каждого пула;
- контроли только по вакансии, только по CV, постоянный score и cosine.

Словарь/IDF/масштабы только train. C={0.1,1,10}; boosting max_leaf_nodes={3,7},
100 итераций, learning_rate=0.05, l2=10, min_samples_leaf=20, early_stopping=False.
Никаких переборов по test. Каждая семья выбирает параметры по validation AP;
pairwise — по среднему внутривакансионному AUC, при равенстве NDCG@5, затем AP.
Общий победитель среди парных моделей выбирается по тем же ranking-метрикам,
если validation содержит >=5 смешанных пулов, иначе по AP (ограничение явно).
Контроли подбирают собственный C на validation, не заимствуют C у парной модели.

Отчёт: AP, ROC-AUC, NDCG@5 и AUC внутри одной вакансии, число пулов, bootstrap
по компонентам; сравнение с вакансией без CV и с исходным представлением.
Для лучшей модели переставляем CV между кандидатами внутри пула (100 seed):
проверяем, есть ли вклад правильного соответствия. Это диагностический тест,
не новая разметка. Срезы Python/SQL, полноты опыта/образования и новых пар.
Модель, split, предсказания, версии и хеши сохраняются, загрузка проверяется.

Без доказанного выигрыша по кандидатам и достаточного покрытия Python/Data
автоматического включения в MVP нет. Даже улучшение здесь не заменяет серверные
тесты навыков, обязательные фильтры, согласия и достижения ФСП.

Методические первоисточники: [scikit-learn: разбиения и оценка](https://scikit-learn.org/stable/modules/cross_validation.html),
[извлечение текстовых признаков](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction).
