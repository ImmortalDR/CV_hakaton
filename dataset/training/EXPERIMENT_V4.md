# V4: расширение корпуса и независимые группы

Протокол фиксируется 10 октября 2026 до обучения и просмотра новых test-метрик.
Работа только в dataset; raw, старые builds, приложение и его БД неизменны.
DeepSeek и внешние API обработки текстов запрещены. Допустима загрузка открытых
весов для локального CPU-инференса, без отправки пользовательских текстов.

## Подготовка

Расширяем прежний отбор названий сильными IT-формулировками в профессиональном
тексте вакансии: разработка/тестирование ПО, администрирование инфраструктуры,
программирование и явно указанные языки/фреймворки. Общие «пользователь ПК»,
Excel, 1С-бухгалтерия, инженер или аналитик сами по себе недостаточны.
Это эвристическая принадлежность к IT, не экспертная разметка профессии.
Перечитываем полные CSV резюме, откликов, опыта и образования потоково.
Связи, предшествующие снимки, конфликтные истории и 30-дневное окно сохраняем
из V3. Метка — записанное принятие/отказ в ответ на отклик, не найм/грейд.
Самостоятельно подтверждённой издателем семантики автора ответа нет.

Все ранее использованные V1/V2/V3 пары включаем в граф связей. Компоненты,
пересекающие их по человеку/CV/вакансии/копии текста, допускаются только в train.
Новые компоненты делим хешем 70/15/15 с фиксированным seed V4. Это новый
отложенный групповой тест относительно наших старых экспериментов, не внешний
и не временной тест. Хронология обеспечивается внутри каждого примера.
Близкие копии (hash word 2–3 gram cosine >=0.95) исключаем из validation/test
относительно train/validation и всех старых примеров. Сохраняем до обучения
списки и SHA. При нехватке теста не меняем seed/пороги ради результата.

## Модели и выбор

Сравниваем word/char TF-IDF cosine, TF-IDF logistic pair и pairwise ranker;
если локальная загрузка открытого энкодера доступна — frozen multilingual E5
(ONNX int8, фиксированный revision), cosine, линейное обучение взаимодействий
эмбеддингов и компактное ранжирование. C={0.1,1,10}; все обучаемые
преобразования только train. Лимит CPU-потоков 2, без CUDA/внешних LLM.
Фиксированные варианты: word/broad/E5/hybrid logistic, pairwise dense logistic,
CatBoost YetiRank (250 итераций, depth={3,5}, learning_rate=0.03, seed=20261010).
Baseline cosine: word, char, broad word, E5; отдельный job-only контроль.
E5 revision 761b726dd34fb83930e26aab4e9ac3899aa1fa78 (экспорт Xenova), int8,
query/passage prefixes, 256 токенов на фрагмент, overlap 32; среднее нормированных
векторов всех фрагментов с повторной нормализацией. Число фрагментов не обрезаем.
Отдельная абляция: TF-IDF на расширенном неразмеченном корпусе вакансий против
словаря только train-пар. Внешние метки/языки не смешиваем с Trudvsem.
Корпус исключает validation/test сущности, их полные версии и близкие копии.
Неразмеченный корпус — до 30 000 уникальных текстов вакансий из существующего
индекса всех профессий, стабильная выборка по SHA текста. Даты строго раньше
последнего обучающего отклика; это не временной прогноз на будущий период.

Основная метрика: macro NDCG@10 по вакансиям с >=10 уникальными людьми,
обоими исходами и одинаковым текстом вакансии. Сначала среднее по снимкам
вакансии, затем по вакансиям; неизвестные не становятся отрицательными.
Малые смешанные группы показываем отдельно (NDCG@min(10,n), within-job AUC).
Выбираем по validation основной метрике при >=10 подходящих вакансий;
иначе по macro AUC малых смешанных групп при >=5, иначе по AP как явно
ограниченному исследовательскому суррогату. Ни одна ветка не использует test.
При равенстве выбираем более простой вариант по фиксированному порядку.
Контроли: постоянный score и модель только по вакансии.

Recall@100: поиск известных положительных кандидатов среди доступных на дату
запроса профилей того же test-раздела; корпус/число кандидатов и допустимые
версии явно указать. Не выдавать его за полноту всей базы или за оценку
неизвестных кандидатов. Нельзя считать только среди уже отобранных top-100.

После заморозки выбора считаем test всех предзаданных вариантов, парные
bootstrap-интервалы по связанным компонентам и диагностику перемешивания CV.
При малом числе компонент интервалы описательные, без заявления надёжности.
Нейросетевой энкодер не называем дообученным, если обучалась только надстройка.
Полное TSDAE/контрастивное дообучение — только при реально доступных ресурсах;
если не выполнено, записать not_run. Производственное включение автоматически
не разрешается ни одним историческим результатом этого эксперимента.

## Ревью до реализации

1. Прочитаны инструкции, карта, протокол, старые prepare/pairs/application_pairs,
   enrich, rank_features, train и относящиеся тесты/отчёты; 17 исходных ответов
   XLSX повторно извлечены и прочитаны. ТЗ повторно сверено с ранее прочитанным
   полным текстом и матрицей. CSV-схемы прочитаны, миллионы записей не объявляем
   вручную прочитанными; сторонний архив не переаудирован.
2. Прослежены source row → явный reply → совпадение четырёх ID → дата создания
   → as-of документы/истории → граф сущностей → train-only признаки → оценка.
   Новый индекс отдельный, исходный SQLite открывается read-only.
3. Проверены требования M05/M07/M15/M20/M23: нет присвоения грейда, изменения
   согласий или профессиональной сертификации; unknown не становится отказом;
   provenance и несовпадение исторической цели с обратным наймом сохраняются.
   Особые риски: два CV одного человека внутри выдачи, новые копии старого test,
   общие короткие названия как ложные дубликаты, усреднение по версиям вместо
   вакансий, будущие версии при retrieval, утечка через неразмеченный корпус.

Методические источники: [E5](https://huggingface.co/intfloat/multilingual-e5-small),
[ONNX](https://sbert.net/docs/sentence_transformer/usage/efficiency.html),
[NDCG](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html).

## Дополнение до обучения: нетривиальный пул поиска

После фиксации split, до обучения/просмотра scores: test содержит 74 человека,
поэтому Recall@100 внутри него тривиален. Сохраняем эту проверку, но отдельно
фиксируем расширенный retrieval benchmark: до 2 000 дополнительных людей из
уже проиндексированных CV, выбранных стабильным SHA person_id, без использования
исходов. Исключаем сущности train/validation/legacy и близкие копии их CV.
Для каждого запроса восстанавливаем CV, опыт и образование строго до его даты;
один человек — один профиль. Добавляем доступные на дату наблюдаемые test-профили.
Положительные — только известные ответы этого запроса; остальные UNKNOWN,
не отрицательные примеры обучения. Сравниваем frozen E5 и train-only TF-IDF.
Это выборочный retrieval benchmark, не полнота по миллионам CV. Сохраняем
манифест документов и запросов до вычисления эмбеддингов и Recall@100.
