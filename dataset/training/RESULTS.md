# Реальные результаты — 9 октября 2026

Подготовлены два набора реальных российских взаимодействий, обучены и сохранены
две модели. Основной предметный вариант — **V2: записанное принятие/отказ в ответ
на отклик в течение 30 дней**. Модель работает локально. Оснований заменять ею
ранжирование MVP пока нет: улучшение персонального подбора не доказано.
Новые датасеты не загружались, DeepSeek/LLM не использовались, рабочая БД не менялась.

## Почему основным стал V2

Весь `invitations.csv` имеет тип «Отклик соискателя». В `responses.csv` находятся
«Приглашение», «Принятие» и «Отказ». Из прямых ссылок `id_reply` для ИТ-подмножества
восстановлены 1380 отказов и 1184 принятия в ответ на отклик; идентификаторы
CV/человека/вакансии/организации совпадают. Инициативные приглашения не относятся
к этой же группе. Поэтому их нельзя безоговорочно смешивать с ответами на отклик.
Направление ответа выведено из связей данных; подтверждения издателя отдельно нет.

V2 содержит **589 уникальных пар**: 251 положительную и 338 отрицательных.
Каждая имеет прямую связь «отклик → ответ», даты и номера записей всех четырёх
CSV. Отсутствие ответа — unknown. Статус «Принятие» не означает трудоустройство,
объективную пригодность или подтверждённый грейд.
Это ответы на уже отправленные отклики. Перенос такого сигнала на основной
сценарий обратного найма — самостоятельный поиск и приглашение работодателем —
ещё не проверен.

Из 6398 ИТ-откликов исключены: 3834 без ответа, 451 с ответом за пределами
30 дней, 594 без предшествующей версии вакансии, 360 без версии CV,
454 с недостаточным профессиональным текстом, 45 с не-ИТ версией вакансии
на дату отклика, 22 с противоречивыми закрытыми историями. Убрано 49 повторных
наблюдений пары. Осталось 589. [Отчёт V2](reports/v2-pairs.json).

Разбиение по связанным компонентам людей/CV/вакансий/копий текста:
**356 train / 121 validation / 112 test**. Внутри эксперимента пересечений этих
сущностей между частями нет. 72 пары нового test уже встречались в V1;
проверка всех видов пересечения приведена в отчёте. V2 — исследовательский
повтор на том же корпусе, не новый нетронутый внешний тест.

## Что обучено и что получилось

TF-IDF слов/биграмм, 4905 признаков словаря; логистическая регрессия на
пересечениях/различиях двух векторов и cosine. Параметр C=1 выбран только
по validation из {0.1, 1, 10}. Пол/возраст/IDs/даты/статусы не являются
структурированными признаками; свободный текст может содержать косвенные признаки.

V2, test — 112 пар, 42 положительные:

| Метод | Average Precision | ROC-AUC |
|---|---:|---:|
| TF-IDF cosine | 0,366 | 0,403 |
| Обученная модель пары | 0,433 | 0,545 |
| Контроль только по вакансии | **0,553** | **0,631** |
| Постоянный score | 0,375 | 0,500 |

Average Precision — метрика упорядочения положительных исходов, не процент
верно подобранных людей. Интервал прироста AP модели относительно cosine:
**[−0,116; +0,192]**, bootstrap 500 повторов по 45 компонентам test. Он включает
ноль. Модель без резюме оказалась лучше модели пары; это не подтверждает
полезность персонального соответствия. Для ранжирования осталось только
4 смешанных пула одной вакансии с одинаковым текстом. NDCG@5 модели 0,650,
у cosine 0,679. Делать из этих чисел рыночное обещание нельзя.

Во всём V2 только 4 пары с отдельным словом Python и 68 с SQL в вакансии.
В test — 2 Python (обе отрицательные) и 15 SQL (2 положительные).
Этого недостаточно для валидации двух специализаций нашего MVP.
[Все метрики и параметры](reports/v2-training.json).

Обучение V2 после подготовки заняло 1,69 с на этой машине; пиковая память
процесса — около 130 MiB. Первый проход многогигабайтных исходников существенно
дольше. Веса реально сохранены:
`dataset/builds/trudvsem-model-v2/model.joblib`.
SHA-256: `fce01c4a8f4fe116bfc62f91bffb1f1033bffc74e815630c28a74dcd8c35628d`.

и постоянного score 0,600. Интервал прироста [−0,179; +0,019]. Инициативные
приглашения и ответы на отклики оказались неоднородной группой наблюдений.

P@5=0,8 в V1 относится всего к одному смешанному пулу — это не «80% качества сервиса».

## Как использовать результат

В репозитории — код, протокол, источники, агрегированные отчёты и ограничения.
Тексты реальных людей, построчные данные и веса остаются локальными.
Инструкция и команды — [README.md](README.md); метаданные локального архива —
[local-release.json](reports/local-release.json). Архив не предназначен для публикации в Git.
Это проверяемое происхождение и воспроизводимые измерения; внешней сертификации,
экспертной разметки профессиональной пригодности и реальных ФСП-грейдов здесь нет.

Дальнейшее улучшение без загрузки новых корпусов: присоединить существующие
workexp/edu строго на дату отклика, отдельно сформировать достаточную выборку
Python/Data и оценивать вклад CV, а не только вакансии. Textovic/Mendeley/IT-корпуса
могут служить материалом для словаря/нормализации, но не источником искусственных
«хороших/плохих кандидатов». Для профессиональной пригодности нужны наблюдения
с известной причиной решения и доказательствами навыков; журнал действий своей
платформы позволяет получать такие сигналы без отдельной команды разметчиков.
