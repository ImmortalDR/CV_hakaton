# V3-CV: устойчивость выбора модели

Дополнение 10 октября 2026 **после** результатов первой серии V3.
Они сохраняются без изменений. На validation из семи смешанных пулов выбран
boosting; на test из четырёх пулов его AUC=0,5. Обогащённая word-модель имеет
лучшие наблюдаемые test-метрики, но выбирать её победителем по test нельзя.

До следующего обучения фиксируем отдельную процедуру выбора:

1. Набор V3-final и test не меняются. Объединяем старые train+validation в dev.
2. Три StratifiedGroupKFold с shuffle=True, seed=20261010. Группы — уже
   построенные компоненты людей/CV/вакансий/копий. Внутри каждого fold ещё раз
   удаляются близкие копии исходного/обогащённого текста. Словари/IDF/масштабы
   обучаются заново, только на обучающей части fold.
3. Те же девять семейств и та же сетка из V3; новых моделей/параметров нет.
   Получаем out-of-fold предсказания, не используя test для выбора.
4. При >=10 смешанных OOF-пулов пары выбираются по macro within-job AUC,
   затем NDCG@5, затем AP. При меньшем числе — по AP с явным ограничением.
   Вакансия-only и CV-only выбирают собственный C по OOF AP.
5. Для каждого семейства сохраняем один параметр, выбранный по OOF.
   Лучший парный вариант определяется тем же правилом. Все выбранные
   модели обучаются на dev; затем однократно считаются метрики прежнего test.
6. Сохраняем результаты по fold, все OOF-пробы локально, модель, хеши,
   повторную загрузку, групповые интервалы и перестановочную диагностику CV.

Эта процедура уменьшает зависимость выбора от одного маленького validation.
Она **не делает уже просмотренный test новым**. Это адаптивное исследование
на старом корпусе; при положительном результате всё равно нужна новая
независимая проверка перед использованием в продукте. Первые результаты V3,
включая неудачно выбранный boosting, не заменяются результатами V3-CV.
