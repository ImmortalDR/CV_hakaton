# Паспорт набора 1.0.0

Задача: проверка обратного найма ФСП. Две специализации Python/Data, три уровня,
правила подтверждения, подбора, приглашения и контактов. Синтетика разрешена ТЗ
§2 и ответами PR.1/FTT.6; два внешних разметчика не являются требованием.

Происхождение и метки разделены: `data_origin` source/adapted/synthetic;
`label_origin` none/source_annotation/team_rule_oracle/simulation. У каждого
объекта source_refs с файлом, ID/порядковым номером CSV-записи или архивным member.
CSV record ordinal не равен физическому номеру строки при многострочных полях.

**Человеческая проверка новых пар: 0. Внешняя сертификация: отсутствует.**
Исходные оценки CareerCorpus принадлежат авторам источника и не подтверждают
подбор Python/Data. Их содержательная шкала не переносится на потребность.
Tianchi satisfied — исторический флаг; отсутствие события и ConFit -1 не
являются независимым доказательством профессионального несоответствия.

Синтетические сценарии проверяют формализованное поведение, а не качество
подбора на всём рынке. Сильные и слабые симулированные участники заданы
конструкцией; высокие различия между ними не доказывают валидность грейда человека.
Симуляции соответствуют выбранному уровню, провал даёт unconfirmed; прежний
подтверждённый грейд и его сохранение проверяются отдельным API-тестом.

48 запросов: dev/test по 24; сущности между ними не пересекаются. Семейства
сценариев общие: не заявляем обобщение на неизвестные типы задач. Для assessment
одни персоны намеренно повторяют разные варианты, split относится к варианту.
Не обучаем веса, не используем результаты ранжирования для эталона. После
доработок по открытым test-ошибкам этот набор становится регрессионным.

Реальные внешние записи остаются external, без нового независимого split.
Повторы и версии сохранены/описаны; near-duplicate-free эталон не заявляется.
Русская выборка ограничена просмотренным префиксом, содержит только очевидные
лексические совпадения Python либо SQL+аналитик; маппинг не проверен экспертом.
Смысл приглашений/отказов ИНИД требует дополнительного исследования.

Реальные записи содержат потенциальные прямые/косвенные идентификаторы и
остаются local-only. Публичная редакция включает собственную синтетику;
regex-проверка не выдаётся за анонимизацию реального корпуса.

Проверки, ошибки и исключения в отчётах фактической сборки. Метрики сторонних
статей не являются метриками MVP. Для профессиональной валидности потребуется
пилот на людях; его отсутствие не маскируется статусом structural PASS.
