Архив содержит 1973 записи: 480 вымышленных профилей, 48 потребностей,
48 пулов, 480 программных меток пар, 432 свидетельства контрольной симуляции,

описание рубрики, снимок функций MVP, источники, манифест, хеши и отчёты.
Данные и собственный код — MIT. Человеческих разметчиков 0; внешнего сертификата
нет. Правильное название: **воспроизводимый оценочный набор с паспортом
происхождения и отчётом проверки**.

## Реально выполненные проверки

Среда: Python 3.12.3, PostgreSQL 16, zlib 1.3, зависимости зафиксированы.

- [38 тестов сборщика](tests.json) прошли: повреждённые записи, ID/ссылки,
  утечки split, неполные пулы, ложная сертификация, приватные файлы, обход путей,
  повторные ID CareerCorpus, независимость предсказаний от меток, воспроизводимость.
- Импорт 1973 записей, повтор без дублирования и откат при искусственном сбое
  проверены в отдельном временном PostgreSQL. Его контейнер удалён после теста.
  В рабочую БД сервиса датасет не импортирован.
- [36 существующих тестов MVP](mvp-tests.json) прошли на `fsp_test`. Два предупреждения
  о будущих изменениях Starlette/AnyIO сохранены, ошибок нет.
- [Проверка распакованного публичного ZIP](standalone-checks.json) прошла с
  программно запрещёнными сетевыми соединениями: validate, matching,
  assessment и dry-run импорта. CRC корректен, отчёт matching и все попытки
  assessment воспроизвелись в точности.
- Сборка public и повторная упаковка в тесте дали одинаковые SHA-256.
  [Повтор локальных адаптеров](local-reproducibility.json) проверяет побайтное
  совпадение всех извлечённых файлов и трёх отчётов.

Основные команды из корня репозитория:

```bash
dataset/.venv/bin/python -m pytest -q dataset/tests
COOKIE_SECURE=false python3 scripts/run_local.py .venv/bin/pytest -q tests
dataset/.venv/bin/python dataset/run.py validate --root dataset/builds/public-v1
dataset/.venv/bin/python dataset/run.py import-db --root dataset/builds/local-v1 --dry-run
```

Первой команде без `FSP_DATASET_TEST_DSN` доступно 37 тестов, дополнительный тест
БД пропускается. Для фактического запуска всех 38 использована отдельная БД
`fsp_dataset_eval` во временном контейнере с портом только на loopback; DSN
передан через окружение. Он не относится к `fsp` или `fsp_test`.
Установка зависимостей описана в основной инструкции. Offline здесь относится
к проверке после установки Python-зависимостей.

`package.json.source_commit` фиксирует HEAD рабочего репозитория при сборке
(072dee7d…); код новых инструментов на тот момент ещё не был закоммичен.
Его точная версия включена в архив и закреплена `build_code_sha256` и общим
манифестом. Изменение HEAD меняет метаданные новой сборки; сравнивайте также
хеши файлов данных. Побайтная повторяемость ZIP проверена в указанной среде
при неизменных входах, коде, HEAD и переданном отчёте API-тестов.

## Измеренное поведение MVP

[Matching](matching.json) использует отдельную рубрику **полного** соответствия.
В каждом split 24 запроса; результаты dev/test одинаковы по агрегатам:

| Сценарий | Запросов | Полностью подходящих в пуле | P@5 с делением на 5 | Фактически выдано |
|---|---:|---:|---:|---:|
| Смешанный пул | 6 | 6 | 1,00 | 8 |
| Никто не соответствует | 6 | 0 | 0 | 8 |
| Обязательный навык неизвестен | 6 | 0 | 0 | 8 |
| Явный фильтр ФСП | 6 | 2 | 0,40 | 4 |

Среднее 0,35 нельзя сравнивать с прежними 0,80: в этом наборе половина запросов
не имеет подтверждённых подходящих кандидатов, а у ФСП-запросов их только два.
Даже идеальная выдача не повысит этот фиксированный знаменатель. Существенное
ограничение: при отсутствии полного совпадения MVP всё равно возвращает
частичные совпадения. В топах каждого split 36 `reject` и 36
`insufficient_evidence`; эти статусы не смешиваются. Проверенные объяснения
соответствуют фикстурам (114/114 оснований на split). Это оценка чистых функций,
а не утверждение о том, как пользователь воспринимает подписи UI.

[Assessment](assessment.json): 480 попыток, 1920 сверок с отдельными решателями,
0 расхождений ответов. Попарная стабильность повторов 0,9186403509. В 360
детерминированных случаях результат совпал с ожидаемым; у noisy ожидаемый
исход не задан. Разность долей верных ответов strong/weak = 1 для 12 семейств —
это следствие модели симуляции, не доказательство профессиональной валидности
теста на людях. Нужен отдельный реальный пилот для такой оценки.

## Локальное дополнение

На сервере: `/root/hakaton/dataset/releases/fsp-eval-1.0.0-local.zip`.
Оно включает публичную часть и внешние записи; всего **215445 записей**.
В GitHub публикуются только [сводка источников](source-audit.json) и
[хеши входов](source_inventory.json), без реальных текстов профилей.

| Источник | Что включено локально |
|---|---|
| Tianchi | 4500 профилей, 20415 описаний, 134841 историческое событие |
| ConFit | 22724 исходные классификационные пары, 300 пулов по 100 кандидатов |
| «Работа в России» | 55 профилей, 27 описаний, 2000 событий с неустановленным направлением |
| TalentCLEF | 2420 validation-qrels Task A English и 25888 Task B |
| CareerCorpus | 302 строки, 301 уникальный исходный ID; обе строки повторного ID сохранены |

Все 37 входов (51 777 408 229 байт с упаковочным архивом) хешированы, перед
локальной сборкой проверены снова; восемь исходных приложений совпадают с
первоначальным манифестом. Это не полное содержательное чтение.

Сохранённые ограничения: 52765 Tianchi-событий ссылаются на 15966 отсутствующих
вакансий; 29536 ConFit ranking-пар не имеют исходного события. У двух пар
`-1` сосуществует с положительным событием. Между legacy split нет общих
ID кандидатов/вакансий, но совпадают тексты вакансий (23/26/1 для
train–valid/train–test/valid–test). Поэтому независимый semantic gold из них
не объявляется. ИНИД — ограниченный последовательный просмотр 100000 строк
каждой основной таблицы, без присоединения workexp/edu и восстановления
временной версии. TalentCLEF test пуст. Шкала CareerCorpus не переносится на
ИТ-грейд или соответствие потребности. Права на публичное распространение
всех реальных документов и их обезличивание не подтверждены.

DeepSeek не использовался. Неизвестное соответствие не размечено как отказ;
исходные события не превращены в квалификацию. HTTPS-сервис сохранил работу;
проверка `/api/health` вернула status=ok. Дальнейшие улучшения ранжирования
должны сравниваться с этим зафиксированным набором и отдельной новой выборкой.
