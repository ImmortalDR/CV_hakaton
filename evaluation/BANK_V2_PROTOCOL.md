# Протокол банка 2.0.0 — зафиксирован до измерения

Шесть категорий остаются прежними. Четыре семейства на категорию: два основного
навыка и два вспомогательного. По два вопроса каждого семейства, всего восемь;
порядок перемешан. Фиксированы структура данных, длины последовательностей и
вид операций внутри семейства. Разные числа не доказывают одинаковую сложность.

Проходной порог команды: 6/8 и не менее 3/4 по основному навыку Python/SQL.
По каждому навыку требуется 75% правильных. Одна случайная ошибка основного
навыка больше не означает автоматический провал. Порог выбран до измерения,
не подгоняется по probe. Длительность — 30 минут, гипотеза для будущего пилота.
Старые версии доступны генератору; попытки оцениваются по своей версии.

Dev: 200 вариантов на категорию, выбор самого частого числового ответа каждого
семейства. Probe: другие 500 вариантов/категорию с независимыми seed. Стратегии:
не знает ничего; знает всё; знает только core; знает только прежние два семейства;
независимые ошибки 10% и 20%; угадывает частый ответ семейства. Нельзя выбирать
новый порог по полученному probe или называть его слепой выборкой людей.

Сравнить 1.2.0/2.0.0: pass rate, попарное совпадение исходов одной модели,
матрицу expected/actual для детерминированных групп, распределения баллов.
Фиксировать наблюдения по каждому семейству: доля верных, частота выбранного на
200 dev частого ответа на probe, strong-minus-weak; групповой разрыв симуляции
не является эмпирической дискриминативностью на людях. При нуле успехов угадывания
показать верхнюю 95% границу Wilson; ноль наблюдений не означает нулевой риск.

Отдельно выполнить независимые решения эталонов, проверку восстановимости версий,
контрпримеры с одной/двумя ошибками core, сохранение старых активных попыток,
API и видимые сценарии браузера. Формальный закон binomial/iid проверить точным
перебором всех масок правильных ответов, не использовать симулятор для эталона
содержания заданий. Реальные результаты людей не симулировать.

Для пилота подготовить обезличенные формы и шаблоны разметки. Не заполнять за
экспертов expected_grade или оценки реалистичности. Данные для human-evaluation
хранятся отдельно, в git входят лишь пустые шаблоны и инструменты.
